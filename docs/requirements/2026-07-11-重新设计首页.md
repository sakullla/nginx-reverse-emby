## 1. 需求摘要
- 问题句：我们要怎样重新设计控制面板仪表盘首页，让管理员登录后能快速判断系统健康、高效触达高频运维任务？
- 使用者：管理员 / 运维人员
- 为什么现在要做：当前首页（`DashboardPage.vue`）采用平铺的统计卡 + 流量模块 + 节点表格布局，信息缺少主次；且只展示节点与 HTTP/L4 规则，无法让管理员快速掌握系统状态。
- 目标与成功标准：
  - 首页围绕节点与规则的核心运维任务重新组织信息分区与视觉层级。
  - 从首页到高频运维任务（如处理离线节点、创建 HTTP/L4 规则、查看节点详情等）不超过 2 次点击。
  - 关键状态（在线/离线节点、规则数量与状态）在首屏分区清晰、一目了然。
- 最小可交付范围：
  - 重新设计 `panel/frontend/src/pages/DashboardPage.vue` 的页面结构、布局与交互。
  - 首页状态区仅聚合真实存在的模块：节点（Agents）、HTTP 规则、L4 规则。
  - 提供高频运维任务的快捷入口，确保 2 次点击内可达。
- 不做事项：
  - 不改动其他页面（agents/rules/l4 列表页、详情页等）的核心逻辑。
  - 不升级全局设计系统、不调整全局导航 / 侧边栏 / 底部导航。
  - 不聚合版本策略、证书、Relay 监听器等模块状态。
  - 不新增后端 API 或数据模型。
  - 不做移动端适配专项。

## 2. 规则与验收
- 关键业务规则：
  - 首页必须只展示真实可用的模块状态，禁止引用不存在的功能（如版本策略）。
  - 快捷入口的点击路径应真实可用，不能链接到未实现页面。
  - 空状态、加载状态、异常状态需保留并适配新布局。
- 关键数据 / 信息：
  - 节点：在线数、离线数、节点列表、节点状态。
  - HTTP 规则：规则总数（来自 agents 聚合）。
  - L4 规则：规则总数（来自 agents 聚合）。
  - 流量数据：现有 `DashboardTrafficModule` 提供的数据。
- 边界与异常：
  - 无节点时的空状态需要保留。
  - 网络异常或加载中状态需要保留。
  - 规则数为 0、节点全部离线等边界情况需要在视觉上可识别。
- 验收标准：
  - AC1：新首页首屏能清晰看到节点状态、HTTP/L4 规则状态，信息分区明确。
  - AC2：从首页到「查看离线节点」「创建 HTTP 规则」「创建 L4 规则」「查看节点详情」等高频任务不超过 2 次点击。
  - AC3：不改动 `router/index.js` 以外的全局导航、不新增全局组件库。
  - AC4：代码构建通过，现有测试（如有）不被破坏。
- 验收与锚点映射：
  - AC1 → R3, R4, R7
  - AC2 → R5
  - AC3 → R6
  - AC4 → R6
