## 1. 问题陈述

- 问题句：我们要怎样重新设计节点详情页，让 SRE 在首屏就能快速判断 `nre-agent` 的健康状态、同步异常位置，并一键触发常见运维操作？
- 当前问题：
  - 节点详情页组件风格不统一，状态徽章、卡片、字体、间距杂乱；
  - 关键健康信息（在线状态、版本、最后心跳、告警）未在首屏聚合；
  - 规则、证书、监听等同步明细与操作入口分散，排障路径长；
  - 缺少暗色模式与响应式支持，影响不同环境下的使用体验。
- 受影响用户 / 角色：SRE / 运维排障人员。
- 为什么现在要做：随着 agent 数量与规则/证书/监听配置增长，现有详情页的信息密度和可读性已成为日常排障效率的瓶颈。
- 现有替代方案 / 当前做法：运维人员需要在列表页与详情页之间反复跳转，并自行从多个字段中推断同步状态。

## 2. 推荐方向

- 推荐方向：以“视觉升级”为契机，对 `AgentDetailPage` 进行信息架构重构：首屏状态栏 + 指标卡片 + 可折叠详情区块；同时全局引入设计 token，并在该页面完整落地暗色模式与响应式。
- 选择理由：
  - 在不改动后端的前提下，显著降低 SRE 的认知负荷；
  - 复用并补齐现有设计系统组件（`BaseBadge`、`AgentMetricTile`、`BaseListCard` 等），避免一次性样式债；
  - 全局设计 token 为后续其他页面迁移打下基础。
- 备选方向与取舍：
  - 方向 A：只做一次性页面样式调整——短期见效快，但无法解决长期设计系统一致性问题；
  - 方向 B：一次性全局所有页面完成暗色/响应式全量迁移——范围过大、回归成本高；
  - 方向 C：借视觉升级扩展后端详情接口——能解决更复杂场景，但超出本次“不动后端”的约束。
- 不选其它方向的原因：本次目标是“在不动后端、不引入内联编辑的前提下，让 SRE 更快排障”，方向 B/C 都会显著扩大范围与风险。

## 3. 目标与成功标准

- 目标：
  - 让 SRE 在打开节点详情页后 3 秒内判断节点健康状态；
  - 让常见运维操作（强制同步、复制注册命令、删除/注销）在首屏或顶部折叠区即可触达；
  - 统一节点详情页的视觉语言，并为全站设计系统迁移提供 token 基础。
- 成功标准：
  - 首屏可见在线状态、模式、版本、最后心跳、告警/错误数；
  - 强制同步、复制注册命令、删除/注销入口位置明确；
  - 节点详情页在暗色模式与响应式下无样式断裂；
  - 所有新增/重构样式通过全局设计 token 表达，而非硬编码值。
- 验收标准：
  - [ ] 顶部状态栏展示节点名、在线/离线状态、模式 badge、版本、最后心跳时间；
  - [ ] 指标卡片区域展示规则数、L4 规则数、证书数、监听数、错误/告警数；
  - [ ] 规则、证书、监听、日志/事件等详情以可折叠卡片或区块呈现；
  - [ ] “强制同步”“复制注册命令”“删除/注销节点”“跳转编辑页”入口可见且可点击；
  - [ ] 暗色模式切换后，节点详情页无肉眼可见样式断裂；
  - [ ] 在 1280px、1024px、768px、375px 宽度下，节点详情页关键信息不溢出、不重叠；
  - [ ] 所有颜色、间距、圆角、字体使用设计 token，代码中不新增 `#xxx` 或 `px` 硬编码常量。
- 验收与需求锚点映射：
  - 顶部状态栏与指标卡片 → R3
  - 轻量运维操作 → R4
  - 暗色/响应式 + 设计 token → R5
  - 字段仅重组 → R6
  - 3 秒可扫描性 → R7
- 度量 / 可观察结果：
  - 页面加载后首屏关键信息可见性可通过截图/Lighthouse 验证；
  - 样式断裂可通过暗色/响应式截图对比检查；
  - 设计 token 使用情况可通过代码审查或样式扫描脚本抽查。

## 4. 范围

- 最小可交付范围 / 本次包含：

  - 前端国际化（i18n）中节点详情页相关文案的梳理与重命名。
- 不包含：
  - 后端 API、数据库、agent 同步协议变更；
  - 节点详情页内联编辑规则/证书/监听；
  - 批量节点操作、列表页重构、其他页面的暗色/响应式全量迁移；
  - 新增专门的后端详情接口或同步历史/审计日志服务。
- 关键约束：
  - 仅使用现有后端返回的 agent 字段，不得新增后端字段；
  - 写操作只能调用现有 API，不得引入新的写接口；
  - 视觉改动必须在设计 token 框架内完成；
  - 保持 Vue 3 / Vite 技术栈不变。
- 依赖与前置条件：
  - 现有设计系统组件（`BaseBadge`、`AgentMetricTile`、`BaseListCard` 等）的接口与可用状态需先确认；
  - 需要了解当前 `AgentDetailPage` 已消费的 API 字段清单；
  - 设计 token 命名规范需与项目现有约定对齐。

## 5. 业务规则与交互要求

- 核心业务能力：
  - 展示单个 `nre-agent` 的注册信息、运行状态、同步配置与健康告警；
  - 提供轻量运维操作的快捷入口。
- 关键业务规则：
  - 在线/离线状态由最后心跳时间或后端返回的 status 决定；
  - 版本字段需要与版本策略/更新机制对齐显示；
  - 规则、证书、监听等配置以“期望状态 vs 当前同步状态”方式呈现时，需用现有字段表达，不新增 diff 数据；
  - 删除/注销操作需要二次确认。
- 关键数据 / 信息：
  - 节点基础：ID、名称、模式、版本、注册时间、最后心跳；
  - 健康：在线状态、错误/告警数；
  - 同步：规则数、L4 规则数、证书数、监听数；
  - 操作：强制同步、复制注册命令、删除/注销、跳转编辑。
- 用户操作与反馈：
  - 点击“强制同步”后显示加载状态，成功后刷新当前页数据，失败时展示错误提示；
  - 点击“复制注册命令”后给出复制成功反馈；
  - 删除/注销需弹窗确认，操作后跳转回节点列表。
- 权限与数据范围：
  - 沿用现有控制平面权限模型；本次不新增权限粒度。
- 状态 / 流程变化：
  - 节点详情页本身不改变节点状态，仅触发已有管理动作。
- 审计、导入导出、历史记录等特殊要求：无

## 6. 边界与异常

- 异常场景：
  - 节点已离线：顶部状态栏突出显示离线 badge，指标卡片仍可展示最后已知配置；
  - 节点未同步完成：对应指标卡片显示警告色或提示文本；
  - 后端接口失败：页面展示错误占位，并提供“重试”按钮；
  - 暗色模式系统偏好切换：页面应响应系统主题变化（如项目已支持）。
- 边界场景：
  - 规则/证书/监听数量为零：显示空状态插画与文案；
  - 节点名称/版本超长：使用截断 + tooltip；
  - 小屏设备（< 768px）：指标卡片垂直堆叠，折叠区块默认收起。
- 空数据 / 重复数据 / 无权限：
  - 空数据：使用统一空状态组件；
  - 无权限：沿用现有“无权限”提示或路由守卫行为，本次不单独设计。
- 兼容与历史数据：
  - 兼容现有 agent 数据结构；历史 agent 无需迁移。

## 8. 不做事项

- 新增后端字段/接口：本次聚焦前端，不动后端数据模型与 API。
- 节点详情页内联编辑规则/证书/监听：避免扩大范围到复杂表单与校验。
