## 1. 需求摘要
- 问题句：我们要怎样重新设计节点详情展示页，让面板运维/管理员打开后一眼看清分区、页面不挤不乱？
- 使用者：面板运维/管理员
- 为什么现在要做：优化展示，提升节点详情页观感与扫读体验
- 目标与成功标准：
  - 节点详情信息按清晰分区组织（如状态、身份、配置、关联等）
  - 间距、对齐、层级统一，页面不显得拥挤、杂乱
  - 不依赖新增业务能力即可完成展示优化
- 最小可交付范围：仅节点详情只读展示页的布局与信息分区重排/美化
- 不做事项：
  - 不新增业务字段或业务能力
  - 不改后端 / API
  - 不做节点列表页改版
  - 不做编辑表单重构
  - 不要求同步统一其他详情页（规则/证书/中继等）

## 2. 规则与验收
- 关键业务规则：
  - 仅调整节点详情展示层的信息组织与视觉布局
  - 现有字段与能力保持可用，不因重设计丢失既有信息
  - 信息应形成可扫读的分区，而不是无层级堆叠
- 关键数据 / 信息：
  - 使用现有节点详情已暴露的数据与状态
  - 不要求新增接口字段；若现有字段展示顺序/分组变化，仍属于展示层调整
- 边界与异常：
  - 字段缺失、空值、离线等现有状态，仍需在新布局中有合理呈现（沿用现有业务语义，不新增状态机）
  - 长文本/多字段场景下仍应保持分区清晰，避免回归到拥挤堆叠
- 验收标准：
  1. 打开节点详情后，主要信息处于明确分区中，而非无结构堆叠
  2. 页面视觉层级清楚：标题/分区/字段对齐与间距统一，整体不挤不乱
  3. 现有节点详情可展示的信息在新设计中仍可访问（无信息丢失）
  4. 无新增 API / 新业务能力 / 列表页与编辑表单改动
  5. 交付范围仅限节点详情只读展示页
- 验收与锚点映射：
  - 验收 1 → R1/R4
  - 验收 2 → R3/R4
  - 验收 3 → R7
  - 验收 4/5 → R5/R6
