## 1. 需求摘要
- 问题句：我们要怎样重新设计 panel 首页，使管理员打开第一屏就能看清"系统正不正常"，并在现有主题体系内获得更精致、层次分明的视觉呈现。
- 使用者：panel 管理员（当前为仓库所有者本人），桌面端为主、手机端兼顾。
- 为什么现在要做：当前首页信息堆叠、重点不突出，最关心的健康状态与常用入口不够直接；视觉观感不满意。
- 目标与成功标准：第一屏一眼看到健康总览（节点/证书/异常）；信息层级清晰（健康 > 流量 > 快捷操作）；首页请求经聚合接口、总请求数较现状减少且接口性能可控；深浅主题下视觉均协调；桌面与手机端浏览后用户确认认可。
- 最小可交付范围：首页页面重排 + 主题内视觉优化 + 后端聚合接口扩展（基于现有 dashboard attention 端点）。
- 不做事项：不改其他页面与全局主题；不新增三大板块之外的新功能模块；不做告警推送/通知能力。

## 2. 规则与验收
- 关键业务规则：
  - 信息优先级固定为：健康状态 > 流量趋势 > 快捷操作。
  - 健康总览数据来自后端聚合接口（扩展现有 dashboard attention 端点优先于另起新端点）。
  - 视觉只使用现有主题 CSS 变量体系，深浅主题自动适配。
- 关键数据 / 信息：节点在线/离线（已有）、证书 30 天内到期（已有）、其他健康信号（open，探索阶段盘点）、流量趋势（已有）、快捷操作入口（已有，取舍 open）。
- 边界与异常：
  - 无异常时健康总览应呈现明确的"一切正常"状态，而非空白。
  - 聚合接口部分数据失败时首页应可降级展示，不整页报错。
  - 手机端布局不劣化，弹窗等继续落在安全区内。
- 验收标准：
  - A1：打开首页，第一屏（桌面 1080p 与常见手机竖屏）无需滚动即可看到健康总览（离线节点、到期证书、异常状态）。
  - A2：健康、流量、快捷操作三个层级的排布次序与视觉权重符合 R1/R2。
  - A3：首页加载的 API 请求总数较改版前减少（方案阶段列出前后对比）。
  - A4：聚合接口响应时间在正常数据量下无明显变慢（方案阶段给出可核验口径）。
  - A5：深色/浅色主题下首页视觉均协调，仅使用主题变量，无写死颜色导致的违和。
  - A6：其他页面与全局主题无可见变化。
  - A7：用户本人在桌面端与手机端浏览后明确认可。
- 验收与锚点映射：A1→R1；A2→R1/R2/R3；A3→R5；A4→R6；A5→R4；A6→R7；A7→R1-R6 总验收。
