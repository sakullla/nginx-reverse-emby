# 需求：内部证书自动轮转与节点隧道双向 mTLS

日期：2026-07-31

## 一屏摘要

- 目标：为内部 PKI 建立可持续轮转、撤销和恢复的生命周期，并将全部 agent 节点隧道升级为严格双向 mTLS（R1-R12）。
- 使用者：面板管理员统一管理；远程 agent 无人值守运行；本地嵌入式 agent 自动安全登记（R7、R9）。
- 范围：内部 CA、控制面/agent/listener 内部证书、节点登记与隧道认证、运维处置、备份迁移和端到端验收（R2-R12）。
- 关键规则：日常轮转不中断且换密钥，身份严格绑定，证书失效后失败关闭，紧急 CA 轮转允许中断（R3-R8）。
- 成功标准：正常轮转、攻击拒绝、离线逾期、撤销重登、重启恢复、备份迁移和紧急处置都有可重复的自动化证据（R12）。
- 不做事项：公网证书、面板/API 用户 mTLS、多活控制面、外部密钥设施或告警、旧协议长期兼容及升级零中断（R13）。
- 非阻塞待定：有效期配置边界、TLS 与密钥基线、错峰/退避/告警默认值、审计保留期及私钥保护封装由技术方案基于代码证据确定（R3、R5、R6、R9、R10）。

## 完整需求

### R1 核实现有内部证书生命周期

研发开始前必须用可定位的实现和测试证据说明现有内部 CA、内部自签证书及 listener 证书的签发、保存、加载、到期检查、续签和轮转行为，并列出与本需求其余条目的差距。界面中的“自动签发”标签、证书存在或到期时间展示不得被当作已经实现自动续签或安全轮转的证据。

验收：

- 现状结论逐项覆盖签发、保存、加载、到期处理、续签和轮转，并能定位到仓库中的实现或测试。
- 对尚未实现、只实现部分或无法证明的能力明确列出差距，不以界面文案替代运行行为证据。

### R2 限定内部 PKI 生命周期边界

自动生命周期只覆盖内部 CA，以及该 CA 为逻辑控制面、远程 agent、本地嵌入式 agent 和 listener 内部端点签发的证书。公网 HTTPS/ACME 证书继续使用既有机制，不得与内部 CA 的签发、续签、轮转或信任状态合并。

验收：

- 内部 CA 与各类内部端点证书能够被明确识别并进入本需求定义的生命周期。
- 公网 HTTPS/ACME 证书不会因内部 CA 的日常或紧急轮转而被重签、撤销或改变信任状态。

### R3 自动续签、错峰重试与失败关闭

内部 CA 默认有效期为 10 年，内部端点证书默认有效期为 90 天；管理员可在技术方案规定的安全范围内配置有效期。任一证书在剩余有效期达到总有效期三分之一时自动进入续签或轮转流程。多节点执行必须错峰；失败必须自动重试、记录原因并在面板告警。失败期间仅可继续使用仍有效的旧材料，证书过期后必须拒绝连接，不得回退到旧认证或忽略过期状态。

验收：

- 使用缩短有效期的测试证书时，自动动作在剩余三分之一阈值附近被触发，并可观察到错峰执行。
- 注入可恢复失败后系统按既定退避重试，保留仍有效的旧材料，并展示可诊断的错误与告警。
- 失败持续至证书过期时连接被拒绝，且不存在明文、单向 TLS 或旧 agent 认证回退。

### R4 日常 CA 换密钥轮转与有限并信

CA 日常轮转每次都生成新的 CA 私钥和 CA 证书，不得复用旧私钥延长有效期。新旧 CA 最多并行受信 30 天；在线节点在并信期内自动取得新信任链和新凭据并完成切换，日常业务和隧道不得出现可感知中断。并信期结束后旧 CA 必须退出信任；逾期仍持有旧凭据的离线节点再次上线时必须被拒绝，并通过新的登记流程恢复。

验收：

- 日常 CA 轮转前后的 CA 私钥和证书指纹均不同。
- 在线远程 agent、本地嵌入式 agent 及相关 listener 在并信期内完成切换，持续业务流量无可感知失败。
- 旧 CA 在不超过 30 天的确定时间退出；超过窗口的离线节点使用旧证书无法接入，但可用新登记凭据恢复。

### R5 端点换密钥与原子切换

逻辑控制面、远程 agent、本地嵌入式 agent 和 listener 每次续签都必须在证书所属端生成新私钥。新证书、私钥和信任链验证成功后才能原子切换；生成、分发或验证失败不得覆盖仍有效的旧材料。私钥不得在控制面与 agent 之间传输，也不得通过日志、面板或 API 明文输出。

验收：

- 每类端点续签后的证书和私钥指纹均发生变化，私钥生成位置可证明为所属端。
- 在新材料生成或验证失败场景中，仍有效的旧材料保持可用且未被部分覆盖。
- 网络、日志、面板和 API 的可观察输出中不出现可还原的私钥明文。

### R6 全部节点隧道强制严格双向 mTLS

逻辑控制面与全部远程 agent、本地嵌入式 agent 之间的节点隧道必须强制双向 mTLS。双方验证签发链、有效期、撤销状态、证书用途和对端身份；agent 证书身份必须匹配稳定节点 ID，服务端证书必须匹配不随机器或地址改变的逻辑控制面身份。无证书、非受信 CA、过期、撤销、用途错误或身份不匹配的证书均必须拒绝，并记录可查询的拒绝事件；不得降级为明文、单向 TLS 或旧认证方式。

验收：

- 双方证书有效且身份匹配时，远程和本地嵌入式 agent 均能建立并维持隧道。
- 分别使用无证书、伪造/非受信、过期、撤销、用途错误、节点 ID 不匹配和逻辑控制面身份不匹配的凭据时，握手或连接均被拒绝。
- 每种拒绝均留下包含对象、时间、结果和原因的可查询事件，且不存在降级连接路径。

### R7 一次性登记、嵌入式身份与升级保留

远程 agent 必须在本地生成并保管独立私钥，通过一次性、短时注册令牌领取绑定稳定节点 ID 的证书；令牌使用一次或过期后不得再次登记。本地嵌入式 agent 由控制面自动安全登记，但必须使用独立身份与私钥，并遵守与远程 agent 相同的 mTLS 校验。首次升级允许维护窗口中断且不要求通过旧隧道预发证书；升级必须保留现有节点 ID、名称、标签及 listener/规则关联，只重建 mTLS 凭据，升级完成后不再接受非 mTLS agent。

验收：

- 有效注册令牌只完成一次登记；复用或过期令牌被拒绝，agent 私钥始终保留在节点本地。
- 本地嵌入式 agent 自动登记后以独立凭据通过同一严格 mTLS 验证，不能绕过证书检查。
- 从旧版本升级后节点 ID、名称、标签及 listener/规则关联保持不变，重新领证后恢复连接，非 mTLS agent 无法连接。

### R8 撤销、强制轮转与紧急 CA 处置

管理员必须能够立即撤销单个 agent 的全部现行证书并断开其既有隧道；被撤销节点只有使用新的短时令牌重新登记后才能恢复。管理员还必须能够强制轮转任一端点证书。怀疑 CA 私钥泄露时，管理员必须能够紧急生成新 CA、立即废弃旧信任并要求受影响节点重新登记；紧急路径不使用日常 30 天并信规则，允许中断。

验收：

- 撤销单个 agent 后其当前隧道立即断开，旧凭据无法重连；使用新令牌重新登记后以新凭据恢复。
- 对任一支持的端点执行强制轮转后，仅该目标完成换密钥和原子切换。
- 紧急 CA 轮转后旧 CA 签发的全部凭据立即被拒绝，节点按重新登记流程使用新信任恢复。

### R9 面板可观测、告警与持久审计

证书管理页必须展示每个 CA 和端点证书的身份、所属节点或服务、签发链、序列号或指纹、用途、有效期、剩余时间、下一次自动动作、当前轮转阶段和最近错误，并提供单节点撤销、端点强制轮转和 CA 紧急轮转入口；高风险操作必须有明确确认。证书申请、签发、续签、轮转、撤销、紧急操作和 mTLS 拒绝必须持久记录触发来源或操作者、对象、时间、结果和原因。续签失败、临近到期和身份异常只要求面板内告警。

验收：

- 管理员能从证书管理页判断每个对象的当前状态、下一动作、轮转阶段和最近失败，并能通过确认流程执行三类处置。
- 所列生命周期与拒绝事件在重启后仍可查询，要求的审计字段完整且能关联到节点或证书。
- 续签失败、临近到期和身份异常在面板内突出显示，本期无需依赖外部通知渠道。

### R10 受保护备份、恢复与跨地址迁移

受保护的控制面备份必须包含 CA、信任链、签发记录、撤销状态及维持逻辑身份连续性所需的信息，同时不得通过常规备份输出提供可直接读取的私钥明文。从备份恢复或将单活控制面迁移到新机器、新服务地址后，必须恢复同一逻辑控制面身份及 PKI 状态；持有有效证书的 agent 只需更新连接地址，无需重新登记，并能继续接受验证、连接和续签。

验收：

- 控制面重启及从受保护备份恢复后，CA 代次、信任链、签发/撤销状态和节点身份保持一致。
- 将恢复实例迁移到新机器和新地址、为该地址准备匹配逻辑身份的服务端凭据后，现有 agent 仅更新连接地址即可恢复隧道并继续续签。
- 常规备份产物和恢复过程的可观察输出不泄露可直接使用的私钥明文。

### R11 单活约束与首次升级中断边界

本期只支持单活控制面，同一 PKI 状态在同一时刻只能由一个有效控制面实例使用。首次从旧认证体系升级到强制 mTLS 允许维护窗口断网，不要求平滑兼容；该例外不得扩展到完成升级后的日常续签和日常 CA 轮转，后两者仍必须满足无可感知中断要求。

验收：

- 运行或恢复流程能阻止或明确拒绝两个控制面同时以同一 PKI 状态提供有效服务。
- 首次升级可在记录的维护窗口内中断，升级结束后只接受 mTLS。
- 日常端点续签和日常 CA 轮转的连续性测试不因首次升级例外而放宽。

### R12 完整自动化端到端验收

交付必须具备覆盖控制面、远程 agent、本地嵌入式 agent、listener 和面板的自动化验证。验证范围包括自动端点续签、日常 CA 无中断轮转、严格 mTLS 正反例、一次性登记、升级关联保留、撤销与重登、端点强制轮转、CA 紧急轮转、续签失败至过期关闭、重启恢复、受保护备份恢复和跨机器/地址迁移，并与受影响的 Go 控制面、go-agent 和前端测试共同通过。

验收：

- 上述每个正常、异常、攻击拒绝和恢复场景都有可重复执行的自动化用例及明确断言。
- 交付验证同时运行受影响模块的局部测试和完整端到端场景，全部结果可追溯到精确命令与退出状态。
- 测试能够区分首次升级允许中断、日常轮转不得中断、日常 CA 最多 30 天并信和紧急 CA 立即废弃四种边界。

## 不做事项

### R13 明确排除的证书、部署与运维能力

本期不改造公网 HTTPS/ACME 证书生命周期，不要求面板/API 用户或公开 Relay/HTTPS 业务客户端使用 mTLS，不支持主备或多活控制面、分布式 CA、外部 KMS/HSM、邮件/Webhook/即时通讯告警、旧非 mTLS agent 的长期兼容、首次升级零中断或通过面板/API 明文导出私钥。这些排除项不得削弱内部节点隧道强制 mTLS、内部私钥保护、单活备份迁移或面板内告警。

验收：

- 交付范围和用户界面不会宣称或依赖上述排除能力。
- 公网证书和公开业务流量继续按既有边界运行，内部节点隧道仍满足 R2-R12。
