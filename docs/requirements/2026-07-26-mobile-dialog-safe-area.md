## 1. 需求摘要
- 问题句：我们要怎样让手机端的弹出框始终显示在浏览器可视安全区内、不被顶部地址栏和底部工具栏/小白条遮挡，使用户能完整查看弹窗内容并正常点击操作按钮。
- 使用者：在手机浏览器上管理 panel 的管理员用户（当前主要是仓库所有者本人）。
- 为什么现在要做：当前在手机上添加/编辑规则时，弹窗标题被地址栏截断、底部「创建规则」等按钮贴边难以点击，影响移动端日常管理操作（有实际截图佐证）。
- 目标与成功标准：在 iOS Safari 和 Android Chrome 上（含地址栏展开/收起两种状态），全站各弹窗打开后标题区完整可见、底部操作按钮完整可见且可正常点击，超长内容在弹窗内部滚动。
- 最小可交付范围：panel 前端全站 Dialog/Drawer 在移动端的统一安全区/可视区适配。
- 不做事项：不改桌面端弹窗表现；不重做移动端弹窗交互形态（全屏页、底部抽屉等改版）；不强制适配微信等 App 内置 WebView。

## 2. 规则与验收
- 关键业务规则：
  - 弹窗（含标题栏、内容区、底部操作区）必须整体落在浏览器实际可视区域与系统安全区内。
  - 修复方式必须是全局统一的（作用于所有弹窗的公共层），新增弹窗自动获得同样保障。
- 关键数据 / 信息：无新增业务数据；纯前端展示层需求。
- 边界与异常：
  - 地址栏展开与收起时可视高度不同，两种状态下弹窗都不得被遮挡。
  - 弹窗内容高度超过可视高度时，内容区内部滚动，标题与底部按钮保持可见。
  - 带底部小白条（Home Indicator）的机型，底部按钮不得落入安全区内侧。
- 验收标准：
  - A1：在 iOS Safari 打开「添加规则」等弹窗，标题「添加规则」与关闭按钮完整可见，不被地址栏压住。
  - A2：同环境下弹窗底部「创建规则」等按钮完整可见、可点击，不被底部工具栏/小白条遮挡。
  - A3：在 Android Chrome 上重复 A1/A2 通过。
  - A4：地址栏展开与收起两种状态下 A1-A3 均通过。
  - A5：抽查至少 3 个不同页面的弹窗（如规则、证书、Agent 相关），表现一致。
  - A6：桌面端弹窗展示与修复前无可见差异。
- 验收与锚点映射：A1→R1/R5；A2→R2/R5；A3→R1/R2/R5；A4→R5；A5→R4；A6→R6。
