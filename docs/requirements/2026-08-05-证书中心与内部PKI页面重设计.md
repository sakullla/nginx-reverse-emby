# 需求：证书中心与内部 PKI 页面重设计

日期：2026-08-05

## 一屏摘要

- 目标：以统一「证书中心」承载公网证书与内部 PKI 双域；对内部 PKI 做深度视觉与交互重做，使巡检与应急处置可操作（R1–R4）
- 使用者：面板管理员在侧栏进入证书中心，日常巡检内部健康/告警，执行登记、轮转、撤销与受保护备份（R1、R3）
- 范围：证书中心入口与一级双域切换；公网证书适配中心壳层；内部 PKI 健康看板驱动的单页深度重做；导航与用户文档入口一致性（R1–R5）
- 关键规则：公网与内部强制分域；不改变 mTLS/控制协议/私钥边界；高风险动作必须显式确认且可跟踪（R2、R4）
- 成功标准：侧栏一入口可切换两域；内部页先状态与待办再处置，关键路径完整可读；公网既有主路径仍可用（R1–R4）
- 不做事项：不重做 PKI/mTLS 后端生命周期；不合并两域对象模型；公网不做同等深度视觉重做；不在侧栏挂平行「内部 PKI」（R6–R9）

## 完整需求

### R1 统一证书中心与一级双域切换

面板侧栏在基础设施下只保留一个证书相关入口（证书中心）。进入后，顶层以一级切换呈现 **公网证书** 与 **内部 PKI** 两个安全域；用户无需再从公网证书页的附属链接“偶然发现”内部 PKI。两域在入口、标题与说明上始终可区分。允许实现选择 tab 同壳或子路由等 URL 形态，但必须满足：侧栏入口统一、两域可切换、可深链到当前域。

验收：

- 从侧栏点击唯一证书入口后，界面可在「公网证书」与「内部 PKI」之间切换，且当前域标识清晰。
- 内部 PKI 不再仅依赖公网证书页角落链接作为主发现路径；设置等处的受保护备份跳转仍可到达内部 PKI 备份能力。
- 直接打开深链（若实现提供）时落在对应域，不会混淆为另一域的列表或表单。

### R2 安全分域与既有安全契约保持

公网 HTTPS/ACME/手动上传业务证书与内部 relay mTLS（CA、endpoint identity、撤销、轮转、登记、受保护备份、审计）继续作为两个独立安全域管理。本需求不得合并签发、信任、对象模型或表单入口，也不得改变既有安全契约：控制链路仍为 HTTP + token；mTLS 仅覆盖 relay 数据面；endpoint 私钥不进入控制面；高风险处置不得静默执行。

验收：

- 公网证书创建/编辑路径不出现内部 CA/identity 签发或撤销入口；内部 PKI 路径不提供公网 ACME/上传业务证书创建。
- 页面文案与边界说明明确两域用途不同，不暗示可用公网证书替代 relay mTLS 身份。
- 既有高风险动作（至少包括身份撤销、强制换证、日常/紧急 CA 轮转、受保护备份导入）仍需用户显式确认后才提交。

### R3 内部 PKI 健康看板驱动的任务结构

内部 PKI 单页按「先状态与待办，再处置」组织，分区顺序固定为：

1. 健康与域状态（如 domain、epoch/security revision、runtime 状态，以及 recovery blocker / 迁移等待等阻断提示）
2. 告警与进行中操作（异常与进行中优先）
3. 身份与证书处置（强制换证、撤销等）
4. CA 轮转（日常 / 紧急）
5. 登记令牌、受保护备份、审计

页内允许使用折叠、抽屉、明细展开等交互，但不得打乱上述任务优先级：打开页面时，健康与待办信息应先于备份/审计细节出现。

验收：

- 打开内部 PKI 域后，在首屏或首要滚动区域即可看到健康/域状态，以及告警或进行中操作（若存在）。
- 身份处置与 CA 轮转入口位于登记令牌、受保护备份、审计之前或同等更高的任务层级。
- 无告警/无进行中操作时有清晰空态，不把空列表伪装成“页面未加载”。

### R4 内部 PKI 视觉与交互深度重做

内部 PKI 不是在现有“技术调试页”上微调分区，而是对其布局、组件、状态表达与关键交互路径做深度重做，使质量对齐面板其它正式页面，并显著提升可读性与可操作性。至少覆盖：

- 布局与视觉：概览卡片、列表/表格、状态徽章、空态、错误态、分区层级与密度；避免无解释的纯技术堆砌作为主阅读路径。
- 语言：对象、状态、下一步与错误以管理员可理解的任务语言呈现；必要时保留可复制的技术标识（serial、fingerprint、id），但不得作为唯一可读信息。
- 交互：刷新/重试、分页或等价浏览、高风险确认、一次性登记令牌展示与关闭清除、操作提交后的进度跟踪与失败恢复提示。
- 能力不回退：概览、告警、身份强制换证/撤销、日常/紧急 CA 轮转、登记令牌、受保护备份导入导出（口令仅驻留单次请求）、审计查询、operation 状态跟踪仍可完成。

验收：

- 管理员无需阅读源码即可完成：查看健康与告警 → 对某 identity 发起强制换证或撤销（含确认）→ 看到 operation 进度或结果；以及发起日常/紧急 CA 轮转（含确认）并跟踪状态。
- 创建登记令牌后 token 仅展示一次，关闭后界面不再保留明文；受保护备份导入/导出不暗示口令被持久保存。
- 加载失败、操作失败、recovery blocker 等异常有明确提示与可执行下一步（如重试、按提示恢复），而不是静默空白。
- 内部 PKI 在视觉与交互完成度上与面板正式业务页一致，不再呈现为未完成的调试拼装页。

### R5 公网证书适配与文档入口一致

公网证书域保留现有主路径：按节点筛选/搜索、列表或卡片浏览、新建/编辑/删除、签发触发、与规则用途相关的业务证书管理。本需求只要求其适配证书中心壳层与分域说明，不做与内部 PKI 同等深度的视觉重做。导航文案、面板内跳转与用户文档中关于「证书管理 / 内部 PKI」入口的描述，须与统一证书中心 + 双域切换一致，避免继续写“侧栏无 PKI、只能从证书页角落进入”且与产品不符的表述。

验收：

- 在证书中心的公网域中，既有新建、编辑、删除、签发与筛选主路径仍可完成。
- 公网域可见分域说明，并提供到内部 PKI 域的明确切换，而不是把内部能力混进公网表单。
- 用户文档与面板内相关说明描述同一入口模型：侧栏证书中心 + 双域切换。

## 不做事项

### R6 不重做 PKI / mTLS 后端生命周期

本需求不重新设计或实现内部 CA 生命周期、自动续签算法、relay 双向 mTLS 协议、enrollment 密码学流程、控制协议认证方式或 agent 私钥托管模型。面板应消费并清晰表达既有能力，而不是借机改后端安全语义。

验收：

- 交付范围说明与实现任务不包含“重做 mTLS / 更换控制面认证 / 改变私钥生成位置”等后端安全语义变更作为本需求必达项。

### R7 不合并两域对象模型

不得把公网证书与内部 identity/CA 合成单一证书列表、单一创建向导或统一“证书类型”枚举来消除分域。跨域只允许导航切换与边界说明，不允许业务对象混管。

验收：

- 不存在一个列表同时作为公网业务证书与内部 tunnel identity 的主管理界面。

### R8 公网证书不做同等深度视觉重做

公网证书页/域以适配中心壳层与保持主路径可用为限；不要求同步重做其全部视觉体系、卡片体系或表单信息架构。

验收：

- 需求验收不以“公网证书页视觉全面翻新”为通过条件。

### R9 不在侧栏再挂平行「内部 PKI」一级菜单

统一证书中心后，侧栏不得再额外增加与证书中心并列的独立「内部 PKI」一级入口，以免双入口分叉。

验收：

- 侧栏基础设施分组中，证书相关主入口只有证书中心一处；内部 PKI 通过中心内切换到达。
