## 1. 需求摘要
- 问题句：我们要怎样把五个资源列表页的节点筛选从横向芯片主路径，改成统一的、可搜索节点 + 按页条件的筛选栏，让多节点场景下筛选可用、可发现？
- 使用者：控制面管理员（在多 Agent 环境下浏览与管理 HTTP/L4/证书/Relay/WireGuard 资源）
- 为什么现在要做：2026-07-11 资源列表页改造已支持跨节点列表、分页与归属展示，但节点筛选交互几乎未变；节点数量增多后，芯片 +「+N 更多」难以定位与切换，需要重建筛选方式需求并单独交付
- 目标与成功标准：
  - 五页均出现统一筛选栏作为主路径
  - 节点为可搜索下拉，含「全部节点」
  - 搜索与启用/状态等条件按页落地
  - 切换条件后列表与分页正确
  - 必要时可扩展后端列表查询以支持新条件
- 最小可交付范围：
  - 五页：HTTP 规则、L4 规则、证书管理、Relay 监听器、WireGuard 配置
  - 筛选栏骨架 + 节点可搜索下拉 + 各页条件区（至少覆盖现有文本搜索能力，并纳入启用/状态类筛选）
  - 去掉（或降为非主路径）横向节点芯片栏
- 不做事项：
  - 多节点同时多选筛选
  - 节点管理页本身改造
  - 默认节点策略 / 跨页筛选记忆大改（沿用上次）
  - 以卡片信息架构重设计为本期目标
  - 为筛选栏单独重做全局导航或首页

## 2. 规则与验收
- 关键业务规则：
  - 节点筛选取值仍为「全部节点」或单一具体节点；不引入多选
  - 「全部节点」下列表展示跨节点资源，资源须可识别所属节点（沿用上次卡片/表格归属能力）
  - 新建资源在「全部节点」下仍须指定归属节点；写操作（启停/删除/诊断等）优先资源自身 agent，行为不因筛选 UI 回退
  - 筛选条件变更应重置到合理页码（如回第 1 页），避免空页
  - 各页条件字段可不同，但筛选栏交互骨架一致（节点控件位置与行为一致）
- 关键数据 / 信息：
  - 节点列表（id、展示名；可选状态用于下拉辅助展示）
  - 当前筛选：agentFilter（全部或 agentId）、文本搜索 q、启用/状态类 filter（按页）
  - 列表分页：page / page_size / total / items（含 agent 归属字段）
- 边界与异常：
  - 无可用节点：筛选栏与列表给出明确空态，不出现可操作的虚假节点
  - 搜索无匹配节点：节点下拉内提示无匹配，不静默失败
  - 列表无匹配资源：列表空态，筛选栏仍可改条件
  - 后端暂不支持某状态筛选时：探索阶段确认是扩展查询参数还是前端仅展示层过滤；扩展查询属本期允许范围
- 验收标准：
  - A1：五页均不再以横向芯片栏作为节点筛选主路径，主路径为筛选栏
  - A2：筛选栏节点控件可搜索，可选「全部节点」与任意已注册节点
  - A3：每页至少具备与资源类型匹配的搜索条件；并具备启用/状态类筛选（字段名与枚举按页定义）
  - A4：切换节点 / 搜索 / 状态后，列表内容与分页计数与筛选一致
  - A5：全部节点与单节点下列表、新建归属、写操作节点解析不回退上次交付语义
  - A6：若新增列表查询参数，前后端约定一致且可测
- 验收与锚点映射：
  - A1 → R1
  - A2 → R2
  - A3 → R3
  - A4 → R4
  - A5 → R4、R5
  - A6 → R5
  - 不做项抽检 → R6
