# Emby / Jellyfin 反向代理与 HTTPS

将客户端连接地址换成自己的域名，由 NRE 节点转发到你有权访问的 Emby 或 Jellyfin 服务。电视和盒子可以直接使用这个域名，无需在客户端配置额外代理。

NRE 不负责媒体存储、刮削或转码。代理是否更快取决于「客户端 → 入口节点 → 后端」的实际线路与带宽，增加一跳并不保证加速。

## 选择适合的接入方式

| 后端在哪里 | 接入方式 |
| --- | --- |
| 有公网地址，VPS 可以直接访问 | HTTP 规则填写后端 HTTP/HTTPS 地址 |
| 与节点在同一内网 | 填写节点可访问的内网 IP 和端口 |
| 在家中内网，VPS 无法直接访问 | 先接入内网 Agent，再按 [Relay 指南](./relay.md) 配置；仅加入 Agent 不会自动打通业务流量 |

初次使用先完成 [快速开始](../getting-started/quickstart.md) 的部署与登录。默认运行时是纯 Go，项目名称保留了历史上的 Nginx 字样；当前面板的转发行为不通过编辑 `nginx.conf` 调整。

## 最小规则示例

假设你的节点能访问 `http://192.168.1.100:8096`：

| 字段 | 示例 |
| --- | --- |
| Agent | 单机部署选 `local`；多节点选实际对外提供入口的节点 |
| 入口域名 | `https://media.example.com` |
| 后端地址 | `http://192.168.1.100:8096`，按实际部署替换 |
| 启用规则 | 开启 |
| 高级选项 | 先使用默认值，出现具体问题再调整 |

将 `media.example.com` 的 DNS 指向入口节点，放行 TCP 80 / 443。保存后等待节点同步和证书签发，再用浏览器打开入口域名。面板自身使用另一个域名，例如 `panel.example.com`。

客户端服务器地址填写 `https://media.example.com`，账号仍然是媒体服务的账号，**不是 NRE Panel token**。如果服务设置了 URL 子路径，请同时核对客户端地址和 [HTTP 规则](./http-rules.md) 的路径配置。

## 验证是否真正可用

只看到登录页还不够。请在实际使用的网络、客户端上检查：

1. **登录与浏览**：登录成功，海报、媒体库和详情能够加载。
2. **开始播放**：播放常用格式的视频，确认画面、音轨和字幕。
3. **拖动进度**：跳到影片中段后能继续播放，再测试暂停和恢复。
4. **持续播放**：播放一段超过以往故障出现时长的视频，观察是否断流或跳到下一集。
5. **比较原站**：条件允许时，同一客户端、同一影片分别直连与经过反代，区分原站或转码问题和转发路径问题。

这些结果与客户端、媒体格式、后端和网络有关；一次连通性检查不能替代上述验证。

## 常见问题

### 页面能打开，播放却失败

先确认客户端确实使用入口域名。检查后端返回的播放地址是否跳转到了客户端无法访问的地址；涉及跳转时参考 [重定向改写](../operations/troubleshooting.md#何时关闭-302-307-重定向改写)。不要把带 token 或签名的完整播放 URL 粘贴到公开 Issue。

### 拖动进度失败或播放中途断流

先做相同视频的原站对比，并记录客户端版本、发生时间、影片码率和是否转码。NRE 的流式恢复依赖后端的 Range 支持及稳定的 `ETag` 或 `Last-Modified`，不能修复所有后端和网络问题。参见 [流式恢复](./http-rules.md#流式恢复)。

### 反代后仍缓冲或速度更慢

分别检查客户端到入口、入口到后端的线路。节点出口带宽、媒体码率、后端限速和转码性能都可能是瓶颈。先确认瓶颈，再决定是否换入口节点或使用出口代理。

### 不知道问题在哪一段

在运行规则的节点执行 [只读连通性检查](../operations/troubleshooting.md#只读连通性检查)。它区分 DNS、连接、TLS 与 HTTP 状态问题，但只检查当前机器直连，不测试视频、Relay、插件后端或规则自定义请求头。

仍需反馈时，请附上 NRE 版本/镜像标签、客户端与后端版本、部署方式、故障时间、原站对比结果和脱敏后的诊断输出。不要附上 `.env`、Panel token、证书私钥或完整播放链接。
